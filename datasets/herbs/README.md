## 网页投影与使用

入口：<http://127.0.0.1:8020/herbs.html>，主站、教师端、数据推演页都有“药材资料”链接。

- `web/data/herbs/catalog.json`：6,859,375 字节；包含原始行号、名称、原文功效/性/味/归经、同名条数。保留全部 50,854 条，24 条一页，不截断整个检索范围。
- `web/data/herbs/quality.json`：记录数、缺失/重复情况、源文件及目录 SHA-256、一致性结果和待核实状态。
- 页面不展示应用、注意事项、炮制、用法；保留原件供团队审阅，不将摘录当作完整安全用药信息。不提供剂量、处方、自动荐药、诊断或疗效评分。
- 检索在浏览器内完成；无搜索上传、后端接口或研究记录写入。名称与功效支持原文子串检索，性/归经支持原文包含筛选。
- 原始条目按文字渲染，不执行其中的 HTML/脚本。文件或目录校验失败显示错误和重试入口。
- 时序推演仍要求原有按天数据；误导入药材格式会提示正确入口，不生成虚构的天数/阴阳值。

## 重建与检查

在平台仓根目录执行，Python/Node 均不需新增依赖，不访问外网：

```powershell
python -X utf8 scripts/build_herb_catalog.py
python -X utf8 scripts/build_herb_catalog.py --verify
python -X utf8 -m unittest discover -s tests -p 'test_*.py' -v
node --test tests/herb-catalog.test.mjs
```

重建会校验双格式一致性后生成目录与质量报告，`--verify` 逐字节核对派生文件。若团队补充来源/许可或完成内容审校，应另建工单记录依据；不得把“格式已核对”改写成“医学已验证”。验收记录见 `challenge_cup/evidence/herbs_2026-11-08/README.md`。
