# 挑战杯参赛工作区

> 本目录是**研究设计与证据工具包**，不是可直接提交的调查报告成稿。  
> 官方负面清单明确禁止「使用 AI 工具代替撰写学术论文、调查报告」与「虚构项目成果」。最终报告必须由参赛学生本人撰写；本目录提供研究设计、问卷、实验平台、数据分析代码、申报素材与答辩编排。仓库中的 3D 指标（如 94%/95%）是**规则模拟参数**，不是实证结果。

## 1. 已读官方要求（本机 `challenge_cup/requirements/`，已 gitignore）

- 《哲学社会科学类参赛作品要求》：社会调查报告，15000 字以内，任选 **经济/政治/文化/社会/生态文明** 一个组别；要求贴近实际、贴近生活、贴近群众。
- 《“挑战杯”竞赛负面清单》：不得 AI 代写论文/调查报告，不得伪造数据、证明材料、项目成果，不得盗用/挂名/重复参赛。
- 《陕西师范大学 2027 年“挑战杯”作品申报书》：A1/A2 申报者，B1 自然科学论文、B2 哲学社会科学调查报告、B3 科技发明制作，C 国内外研究概述，D 推荐者。
- 《评审要点》：
  - 哲学社会科学类：科学性 30 + 先进性 30 + 现实意义 30 + 规范性 10。
  - 科技发明制作：科学性 30 + 先进性 30 + 现实意义 30 + 规范性 10，但更看技术方案、成熟度、推广价值。

## 2. 赛道建议（需与学院/导师确认）

> **2026-11 方向更新：** 按你最新的想法，项目重心从“面向青年的文化传播”调整为“**面向医学生的数据驱动 3D 教学系统**”：队友提供病例/教学参数数据集，系统把“用药前后阴阳气血变化”映射到真实解剖与经络。主赛道建议改为 **B3 科技发明制作 B 类（信息技术/生命科学）**；若学院要求社科类，则报 **B2 社会组（教育/健康）**，把系统作为教学干预工具。旧的 B2/C 文化版材料保留在 01–08，作为备选。

| 方案 | 适合度 | 说明 |
|---|---|---|
| **B3 科技发明制作 B 类（信息技术/生命科学）** | **首选（医学生系统版）** | 以“真实解剖 + 经络投影 + 数据接入 + 用药时序推演 + 教学研究”为发明点；B3 看技术方案、成熟度、应用/推广价值，需要有研究报告、技术指标、测试/演示数据。 |
| B2 哲学社会科学类社会调查报告（D 社会组：教育/健康） | 备选 | 以“医学生中医理论理解”为教育问题，把系统作为干预工具，做前后测/对照实验；若学院只允许社科类，选这个。 |
| B2 哲学社会科学类社会调查报告（C 文化组） | 备选（旧叙事） | 以“中医药文化传播”为问题；适合把系统定位为文化传播工具，但与“医学生 + 数据集”新方向不如 B3 贴合。 |
| B1 自然科学类学术论文 | 不建议 | 核心不是基础科学发现；除非能做严格的人体/医学实验。 |

**建议标题（供与导师定稿，不是最终成稿）**

> 《络象经纬：面向医学生的数据驱动阴阳二气与经络 3D 教学系统》

备选：
> 《基于真实解剖与用药时序数据的医学生中医阴阳经络 3D 教学系统》
> 《让阴阳“可推演”：医学生中医理论数据驱动 3D 教学系统的设计与效果研究》

**研究问题（医学生版）**

> 导入病例/教学参数数据集后，3D 系统能否帮助医学生更好地理解阴阳二气、经络空间关系，以及用药引起的阴阳气血变化？其作用机制、适用边界与教学推广路径是什么？

**核心创新（用事实表述，不夸大）**

1. **数据接入**：队友提供 CSV/JSON 时序数据（阴、阳、气、血、瘀滞、炎症、阻滞经络、用药事件），系统校验、插值并驱动 3D；不是写死的演示动画。
2. **真实解剖 + 经络投影**：BodyParts3D 4.0 皮肤/骨骼/五脏六腑，26 条经络投影到真实体表，和数据集指标同步变化。
3. **用药时序推演**：时间轴 + 阴阳气血曲线 + 用药事件标记 + 3D 器官/经络变化，帮助医学生把“证候—用药—变化方向”连起来。
4. **可研究、可合规**：数据来源/许可/警告可见；本地解析不上传；研究模式可做前后测；明确“教学参数不是临床疗效证据”。

> 注意：当前“智能体/推演”是**本地规则 + 数据映射**，不是大模型、不是临床决策系统；参赛材料必须如实写。数据集的 0–1 参数是教学参数字段，不等同于生理测量或疗效证据。

## 4. 当前原型的真实状态

- Web：`web/`，本地 HTTP 服务；26 条投影经络、14 个器官、皮肤透视、太极/流注环、症状匹配、方剂示例、0–28 天模拟；浏览器实测通过。
- **评委速览**：`web/judge.html`，一页展示定位、四个演示模块、可核验工程指标、研究设计、评分点对照、合规边界和 3 分钟路线；支持打印 A4 PDF。
- **工程证据**：`challenge_cup/evidence/`，记录页面加载、FPS、三角面、draw calls、视口和控制台 error；只作为工程记录，不是实验结论。
- **数据推演**：`web/dataset.html`，导入队友 CSV/JSON → 案例/时间轴/阴阳气血曲线/用药事件 → 3D 状态；无后端，已实测 CSV、JSON、演示数据、错误提示。
- 研究模式：`web/research.html`，知情同意 → 前测 → 3D/图文学习 → 后测 → 匿名 CSV；无后端、症状不上传；已实测实验组/对照组两条流程。
- Unity：`unity/TCMYinYang`，Unity 6000.0.85f1 + Built-in RP，D3D11 启动；14 器官/骨骼/经络加载。
- 解剖数据：BodyParts3D 4.0（CC BY-SA 2.1 Japan）；肺实质为程序化补建。
- **未验证**：真实用户学习效果、临床准确性、长期留存；这些必须通过研究采集，不能用模拟指标代替。

## 8. 研究模式怎么用

![数据推演](../docs/dataset_preview.png)

![研究模式](../docs/research_mode_preview.png)

```powershell
# 在平台仓根目录
powershell -ExecutionPolicy Bypass -File deploy/start_preview.ps1
# 演示：     http://127.0.0.1:8020/
# 数据推演： http://127.0.0.1:8020/dataset.html
# 研究模式： http://127.0.0.1:8020/research.html
```

1. 主试在左侧填匿名编号（如 `E-001` / `C-001`），选择实验组（3D）或对照组（图文），点“应用设置”。
2. 受试者阅读知情同意、勾选全部同意项 → 前测。
3. 实验组在新标签打开 3D 智能体，按任务单操作；对照组阅读同页图文材料。
4. 勾选“已完成学习任务” → 后测 → 提交。
5. 点“下载 CSV”，与 `data/templates/experiment_items_template.csv` 列名一致，可直接用 04 脚本分析。
6. “开始下一位受试者”会清除本机作答；请先导出上一位的数据。

> 研究模式只使用标准案例，不收集个人症状；数据只存在当前标签页的 sessionStorage，没有后端上传。

**数据推演页**：主试/队友把 `web/data/dataset_template.csv` 或 JSON 交给系统，页面显示案例、曲线、用药事件与 3D 变化；字段规范见 [`docs/数据接入规范.md`](../docs/数据接入规范.md)。演示文件 `web/data/dataset_demo.csv` 只是格式演示，不是真实病例或实验结果。
