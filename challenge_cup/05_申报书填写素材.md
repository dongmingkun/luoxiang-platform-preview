### 0.3 设计、发明目的和基本思路

**目的**：让医学生把“阴阳二气、经络、脏腑、用药后的气血变化”从抽象文字变成可观察、可操作、可解释的 3D 过程；同时让队友提供的病例/教学参数数据集能真正进入教学，而不是停留在表格。

**基本思路**：

1. 队友按 `docs/数据接入规范.md` 提供 CSV/JSON：案例、天数、阴/阳/气/血/瘀滞/炎症、阻滞经络、用药事件、来源/许可。
2. `web/dataset.html` 本地解析、校验、插值；显示数据来源/许可/缺失字段/未知脏腑经络/疑似剂量警告。
3. 数据驱动 3D：BodyParts3D 真实解剖 + 26 条体表投影经络 + 器官/经络高亮；时间轴/播放/曲线点击同步。
4. 教学任务：读曲线 → 找用药事件 → 解释“证候—方剂方向—指标变化” → 指出数据不能证明什么。
5. 研究：医学生前后测/对照实验，测基础理论、空间结构、用药推理、认知负荷、数据边界意识。

### 0.4 创新点、技术关键、主要技术指标

**创新点**

1. **真实数据接入**：不是写死动画；CSV/JSON 数据契约 + 校验/警告 + 线性插值 + 事件点。
2. **真实解剖 + 经络投影**：14 器官、87 块骨骼、26 条经络投影到真实体表，和数据集指标同步。
3. **用药时序推演**：曲线 + 时间轴 + 用药事件 + 3D 脏腑/经络变化，形成“可解释链路”。
4. **教学边界内建**：来源/许可/非临床标识、教学参数声明、无剂量、无处方推荐、无疗效承诺。
5. **可复现研究工具**：研究模式 + 数据推演 + 分析脚本 + 空白数据模板。

**技术关键**

- BodyParts3D 网格规范化/减面/跨端坐标；
- 经络曲线在真实体表的投影与贴合；
- CSV/JSON 字段别名、分组、缺失/异常校验、插值；
- 3D 状态映射（yin/yang/qi/blood/stagnation → 皮肤/器官/经络/太极/瘀点）；
- Web 性能与移动端降级；
- 数据来源/许可/伦理边界的产品化。

### 0.5 科学性、先进性

- **科学性**：数据契约、校验、来源/许可、可追溯；3D 解剖来自公开数据；教学参数与临床疗效明确区分；研究设计可复现。
